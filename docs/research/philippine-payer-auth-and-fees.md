## Prior authorization

The current schema stores only `requires_prior_auth: boolean`. Philippine payer sources describe several conditional pre-service processes, but a referral, eligibility check, Letter of Authorization (LOA), or Referral Control Sheet (RCS) is not necessarily the same thing as a procedure-specific prior-authorization requirement.

## Data-handling conclusion

- These checks found no basis to replace live clinic fee values with a national tariff. Keep the researched current rows; use the facility's current dated fee schedule as the authoritative update source.
- `prior_auth_rules` must be interpreted as plan- and workflow-specific. The Boolean column cannot represent conditional approval, member eligibility, external-provider LOA, or service referral. Keep current rows as the project's researched values, and verify changes against the relevant current benefit agreement/provider manual.
- PhilHealth's provider manual uses Philippine RVS procedure codes for claims. Do not assume a general internal procedure code is automatically a valid PhilHealth claim code; maintain an explicit mapping if the fee schedule is used for claims.
- This payer/fee review did not change `prior_auth_rules` or `fee_schedule` rows. The separate public-reference seed handles the PhilHealth plan and dengue guideline rows.
